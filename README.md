# Мессенджер

Современный веб-мессенджер для удобного общения.

## О проекте

Проект находится в активной разработке. Это учебный проект, созданный в рамках курса Middle Frontend Developer от Яндекс Практикума.

**Текущий статус**: 🚧 В разработке

## Функциональность

### Реализованные страницы

- **Авторизация** (`/`) — страница входа в систему
- **Регистрация** (`/sign-up`) — страница регистрации нового пользователя
- **Чаты** (`/messenger`) — страница со списком чатов и диалогами с поддержкой WebSocket
- **Профиль** (`/settings`) — страница настроек пользователя
- **Ошибка 404** — страница для несуществующих маршрутов
- **Ошибка 500** (`/error500`) — страница для серверных ошибок

### Основные возможности

- ✅ **Компонентная архитектура** — собственная реализация компонентного подхода на основе класса `Block`
- ✅ **Роутинг** — собственный роутер с поддержкой приватных маршрутов и защитой от неавторизованного доступа
- ✅ **Работа с формами** — сбор данных из форм, валидация полей ввода
- ✅ **Валидация данных** — проверка корректности введенных данных (логин, пароль, email, телефон, имя, фамилия)
- ✅ **Обработка событий** — система событий через EventBus
- ✅ **HTTP клиент** — класс для работы с API (GET, POST, PUT, DELETE)
- ✅ **WebSocket клиент** — поддержка реального времени для обмена сообщениями
- ✅ **State Management** — централизованное хранилище состояния приложения
- ✅ **API интеграция** — работа с REST API Яндекс.Практикума (авторизация, чаты, пользователи)
- ✅ **Шаблонизация** — использование Handlebars для рендеринга компонентов
- ✅ **Контроллеры** — слой контроллеров для управления бизнес-логикой (Auth, Chats, User)

### Компоненты

- **Input** — переиспользуемый компонент поля ввода с поддержкой валидации и отображения ошибок
- **Button** — компонент кнопки с поддержкой иконок и текста
- **Form** — компонент формы с автоматическим сбором данных
- **Link** — компонент ссылки для навигации
- **Error** — компонент для отображения ошибок
- **Chat** — компонент чата с отображением сообщений
- **ChatListItem** — компонент элемента списка чатов
- **ContextMenu** — компонент контекстного меню
- **Modal** — компонент модального окна

## Используемые инструменты

### Языки и технологии

- **TypeScript** — типизированный JavaScript для надежности кода
- **Handlebars** — шаблонизатор для создания динамических HTML-шаблонов
- **Sass/SCSS** — препроцессор CSS для удобной работы со стилями

### Инструменты разработки

- **Vite** — быстрый сборщик и dev-сервер
- **vite-plugin-checker** — плагин для проверки TypeScript, ESLint и Stylelint во время разработки
- **ESLint** — линтер для проверки качества JavaScript/TypeScript кода (flat config)
- **Stylelint** — линтер для проверки CSS/SCSS кода
- **TypeScript Compiler** — проверка типов на этапе компиляции
- **Jest** — фреймворк для тестирования
- **Husky** — инструмент для настройки Git hooks

### Архитектура

- **Компонентный подход** — собственная реализация компонентной системы на основе класса `Block`
- **EventBus** — паттерн для управления событиями между компонентами
- **Роутинг** — собственный роутер с поддержкой приватных маршрутов
- **State Management** — централизованное хранилище состояния через Store
- **MVC паттерн** — разделение на контроллеры, модели и представления
- **Модульная структура** — разделение на компоненты, страницы, сервисы, контроллеры, API и утилиты

## Установка и запуск

Для работы с проектом необходимо:

1. **Склонировать репозиторий**

```bash
git clone https://github.com/dudina-ma/middle.messenger.praktikum.yandex.git
cd middle.messenger.praktikum.yandex
```

2. **Установить зависимости**

```bash
npm install
```

3. **Запустить проект**

```bash
npm run start
```

### Скрипты

- `npm run dev` — запуск в режиме разработки на порту 3000 (с автоматической проверкой TypeScript, ESLint и Stylelint)
- `npm start` — сборка и запуск проекта на порту 3000
- `npm run build` — сборка проекта для продакшена
- `npm run typecheck` — проверка типов TypeScript
- `npm run lint` — проверка кода (TypeScript, ESLint, Stylelint)
- `npm run lint:fix` — автоматическое исправление ошибок линтера
- `npm run lint:css` — проверка только CSS/SCSS
- `npm run lint:css-fix` — автоматическое исправление CSS/SCSS
- `npm test` — запуск тестов Jest

4. **Открыть в браузере**

Приложение будет доступно по адресу: http://localhost:3000

## Тестирование

Проект использует **Jest** для написания и запуска тестов. Файлы с тестами хранятся рядом с тестируемыми элементами.

### Структура тестов

Тесты находятся в тех же папках, что и тестируемый код:
- `src/services/router.test.ts` — тесты для роутера
- `src/services/block.test.ts` — тесты для компонента Block
- `src/services/http-client.test.ts` — тесты для HTTP клиента

### Запуск тестов

```bash
npm test
```

### Написание тестов

Тесты написаны с использованием Jest и моков для проверки функциональности:
- Роутер — проверка навигации, приватных маршрутов, History API
- Компонент Block — проверка жизненного цикла, событий, обновления DOM
- HTTP клиент — проверка методов запросов, обработки ошибок, заголовков

## Проверка кода

### Автоматическая проверка во время разработки

Проект использует **vite-plugin-checker** для автоматической проверки кода во время разработки:

- **TypeScript** — проверка типов в реальном времени
- **ESLint** — проверка качества кода (flat config)
- **Stylelint** — проверка CSS/SCSS стилей

Ошибки отображаются в консоли Vite и в overlay браузера при запуске `npm run dev`.

### Pre-commit hooks

Проект настроен с использованием **Husky** для автоматической проверки кода перед коммитом:

- **Линтер** — проверка TypeScript, ESLint и Stylelint
- **Тесты** — запуск всех тестов Jest

Если проверки не проходят, коммит блокируется.

Настройка находится в `.husky/pre-commit`.

### Ручная проверка

```bash
# Проверка всех линтеров
npm run lint

# Автоматическое исправление ошибок
npm run lint:fix

# Проверка только TypeScript
npm run typecheck

# Проверка только CSS/SCSS
npm run lint:css
```

### Требования

### Настройка окружения

После клонирования репозитория:

1. Установите зависимости:
```bash
npm install
```

2. Настройте Git hooks (выполняется автоматически через `prepare` скрипт):
```bash
npm run prepare
```

3. Запустите проект в режиме разработки:
```bash
npm run dev
```
